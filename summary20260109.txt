# Easy PDF Reader - 開發摘要 (2026-01-09)

## 1. 今日核心需求
*   **頁面組織能力提升：** 支援多份 PDF 檔案合併、選取頁面替換、以及選取項導出（單一或多檔案）。
*   **介面精緻化：** 解決導航列高亮偏移、Grid 模式捲動重置、工具列重疊位移等細節瑕疵。
*   **UI/UX 改進：** 實施「操作藥丸 (Organize Pill)」浮動工具列，並導入 768px 響應式邏輯與更直覺的圖示。

## 2. 重大技術變更
### 後端 (Rust - lib.rs)
*   **多文件映射架構：** `AppState` 升級為 `HashMap<String, PdfDocument>`，支援同時渲染來自多個不同路徑的 PDF 頁面。
*   **指令解耦與死結消除：** 提取 `perform_save` 內部函數，解決了 `export_individual_pages` 在批次呼叫 `save_document` 時產生的 Mutex 狀態鎖定衝突。
*   **智慧匯入邏輯：** 實作 `import_pages` 指令，支援起始插入、選取點前後插入及「替換」模式。

### 前端 (React - App.tsx & Components)
*   **導航系統大一統：** 移除獨立的 Bookmarks 分頁，將書籤標題直接映射為頁面名稱。
*   **絕對幾何中心工具列：** 工具列改為 `1fr auto 1fr` 的 CSS Grid 佈局，確保模式切換器永遠鎖死在視窗中央。
*   **Strict Intent Lock (高亮修正)：** 引入同步 Ref 鎖定機制，解決了點擊 N 頁卻跳回 N-1 的頑固 Bug。
*   **穩定網格容器：** 將 `VirtuosoGrid` 的組件定義靜態化，解決了點擊選取時畫面跳回頂端的瑕疵。

## 3. 解決的關鍵瑕疵 (Bug Fixes)
*   **高亮 N-1 問題：** 透過中點判定與 1.2 秒的強制意圖鎖定成功排除。
*   **長頁面破圖問題：** 透過 `object-contain` 约束成功修復。
*   **水平捲動條：** 實施寬度鎖定，避免視窗縮窄時頁面比例失真。

## 4. 目前已知未解決問題 (Persistent Functional Blocks)
*   **匯入/導出功能持續受阻：** 儘管 UI 與後端架構已更新，但目前仍無法順利匯入外部檔案，且「分割導出 (Export Split)」指令雖然觸發了通知，卻未能實際在磁碟生成檔案。
*   **已嘗試的方法：**
    1.  **指令嵌套解耦：** 試圖透過將指令邏輯轉移到私有 Rust 函數來避開 Mutex 鎖定死結。
    2.  **狀態同步優化：** 在前端重寫多個異步 Handler，確保路徑正確傳遞。
    3.  **UI 事件隔離：** 使用 Ref 排除法與事件冒泡控制來修正選單 Toggle。
*   **無法成功的原因分析：** 
    *   **核心控制柄衝突：** `pdfium-render` 的 Document Handle 在跨指令或異步調用時，可能與 Tauri 的 `State` 管理機制產生深層衝突，導致控制柄在背景悄悄失效或被鎖定。
    *   **多路徑映射複雜度：** 在虛擬頁面與多份來源檔案之間的映射邏輯（(Path, Index) -> VirtualIndex）在 Rust 層級可能存在未被捕獲的 Panic 或靜默錯誤，導致執行流在中途終止。

## 5. 未來展望
*   **下一步：** 必須針對 Rust 的多文件 Handle 生命週期進行壓力測試，找出導致檔案操作無效的靜默崩潰點。功能面則準備進入 Phase 13 的「標註編輯」功能。
